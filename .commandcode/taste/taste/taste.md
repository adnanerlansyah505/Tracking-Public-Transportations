# Taste
- Expects the agent to read and follow the project's in-repo guidance before writing code — the design skill under `.agents/skills/` plus the PRD/guideline/task docs referenced with `@` — rather than deciding conventions on its own. Confidence: 0.75
- Wants backend models/endpoints shaped to match the frontend's existing types and dummy data (same field names/shape) instead of inventing a parallel contract. Confidence: 0.65
- When asking to wrap up, wants the agent to skip further checking/verification and just clean up: remove temporary diagnostic files/logs, stop background processes, and revert any temporary instrumentation edits so the repo is left untouched. Confidence: 0.55
- Pushes back with "fix it properly" when a bug report returns: expects a genuine root-cause fix verified by reproducing the issue (including driving the real running app/browser when needed), and treats an unverified or plausible-sounding explanation as not done. Confidence: 0.6
- Reports bugs by pasting raw evidence of the failure — a screenshot of the failing screen (expects the agent to inspect the image itself, URL, exact error text, stack) or the full exception/stack trace (occasionally with the offending file/line from the IDE) — and expects the agent to read the trace and fix the real root cause rather than just the surface symptom. Confidence: 0.55
- Prefers changes to authoritative/user data to go through an admin-reviewed request → approval workflow (e.g. a driver submits a vehicle/operation change request, an admin reviews it, and approving applies the change) rather than self-service immediate writes. Confidence: 0.6
- Welcomes the agent proactively adding sensible complementary features beyond the literal request — explicitly invites "feel free to add anything else relevant" — rather than implementing only the narrow spec. Confidence: 0.55
- Expects a multi-part request to be carried through to full completion across all its parts, following up with "continue"/"complete all the tasks" when the agent stops short (also does this when the agent's turn is cut off, e.g. by a context/token blow-up). Confidence: 0.55
- Expects the app's public-facing features to keep working for signed-out visitors: a public page's core action (e.g. searching for the nearest angkot from the landing page) must not fail with an auth error, so such endpoints should support optional authentication instead of requiring a session. Confidence: 0.6
- Expects signed-out visitors to be first-class participants in two-sided flows, not merely to receive a non-error response: when an anonymous visitor uses a feature, the other party must be able to see/detect them too (e.g. a driver's "find passengers" list must include anonymous searchers), so a deliberately trace-less anonymous path is treated as a bug. Confidence: 0.5
- Usually goes with the agent's proposed "(Recommended)" option when asked to choose between approaches, so offering a clear opinionated default is effective — though will deliberately override it for a stronger technical preference (chose Socket.IO over the recommended dependency-free SSE). Confidence: 0.5
- Wants two-sided features to be symmetric: when a capability benefits one party in a two-sided interaction, the reciprocal direction should be provided too — explicitly asks for it "from the driver's perspective, and vice versa" so both sides get the same actionable information. Repeats this whenever a role-specific view only implements one side (called out that a driver's view showed no route to the passenger's location, "it only reflects the user's perspective"). Confidence: 0.6
- Expects long-running processes the agent starts (e.g. the freshly built backend on port 3000) not to be left running: a stale listener holding the app port is treated as something to find and kill, since it later resurfaces as an `EADDRINUSE: address already in use` error when the server is started again. Confidence: 0.5
- Expects potentially unbounded lists (e.g. notifications) to be fetched incrementally — asks for lazy-loading pagination / a "load more" control — rather than loading the whole collection up front. Confidence: 0.5
- Thinks about alternate/edge-case paths through a flow (e.g. Google/OAuth sign-up skipping required registration fields such as vehicle details) and expects the app to handle them: the account must still be usable and the missing required data completable afterwards. Confidence: 0.5
